# Render Deployment Guide

This guide will help you deploy CasaVera Furniture to Render with proper database, backend, and frontend connections.

## Prerequisites

1. **Render Account**: Sign up at [render.com](https://render.com)
2. **GitHub/GitLab Repository**: Your code should be in a Git repository
3. **Google OAuth Credentials** (if using): Update redirect URI after deployment

## Deployment Steps

### Step 1: Connect Your Repository

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click "New +" → "Blueprint"
3. Connect your Git repository
4. Select the repository containing this project
5. Render will detect `render.yaml` automatically

### Step 2: Review and Deploy

1. Render will parse `render.yaml` and show you 3 services:
   - **PostgreSQL Database** (`casaverafurniture-db`)
   - **Backend API** (`casaverafurniture-backend`)
   - **Frontend** (`casaverafurniture-frontend`)

2. Click "Apply" to create all services

3. Render will:
   - Create the PostgreSQL database first
   - Deploy the backend (which will run migrations)
   - Deploy the frontend (which will build and serve)

### Step 3: Configure Environment Variables

After services are created, you may need to manually set some environment variables:

#### Backend Environment Variables

Go to `casaverafurniture-backend` → Environment:

**Required:**
- `APP_KEY`: Auto-generated by Render (check if it's set)
- `GOOGLE_CLIENT_ID`: Your Google OAuth Client ID
- `GOOGLE_CLIENT_SECRET`: Your Google OAuth Client Secret
- `GOOGLE_REDIRECT_URI`: Should be `https://your-backend-url.onrender.com/api/auth/google/callback`

**Optional (for production):**
- `MAIL_MAILER`: Set to `smtp` for email
- `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`: Email service credentials
- `REDIS_URL`: If using Redis for caching/queues

#### Frontend Environment Variables

Go to `casaverafurniture-frontend` → Environment:

**Required:**
- `VITE_API_URL`: Should auto-populate from backend service
- `VITE_APP_NAME`: "CasaVera Furniture"

**Optional:**
- `VITE_PUSHER_APP_KEY`: If using Pusher for real-time features
- `VITE_PUSHER_APP_CLUSTER`: Pusher cluster

### Step 4: Update Google OAuth Redirect URI

1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Navigate to APIs & Services → Credentials
3. Edit your OAuth 2.0 Client
4. Add authorized redirect URI:
   ```
   https://your-backend-url.onrender.com/api/auth/google/callback
   ```
5. Update `GOOGLE_REDIRECT_URI` in Render backend environment variables

### Step 5: Verify Deployment

1. **Check Backend Health:**
   ```
   https://your-backend-url.onrender.com/up
   ```
   Should return: `{"status":"ok"}`

2. **Check API Endpoint:**
   ```
   https://your-backend-url.onrender.com/api/home
   ```
   Should return JSON data

3. **Check Frontend:**
   ```
   https://your-frontend-url.onrender.com
   ```
   Should load the homepage

4. **Test Database Connection:**
   - Backend logs should show successful database connection
   - No errors about missing tables

## Service URLs

After deployment, you'll get URLs like:
- **Database**: Internal (only accessible from backend)
- **Backend**: `https://casaverafurniture-backend.onrender.com`
- **Frontend**: `https://casaverafurniture-frontend.onrender.com`

## Connection Flow

```
Frontend (Vue) 
    ↓ (API calls)
Backend (Laravel API)
    ↓ (Database queries)
PostgreSQL Database
```

All connections are automatically configured via `render.yaml`:
- Frontend → Backend: Via `VITE_API_URL` environment variable
- Backend → Database: Via database connection environment variables
- CORS: Configured in backend to allow frontend domain

## Troubleshooting

### Issue: Frontend can't connect to backend

**Symptoms:** CORS errors or 404s when calling API

**Solution:**
1. Check `VITE_API_URL` in frontend environment variables
2. Should be: `https://your-backend-url.onrender.com/api`
3. Verify backend URL is correct
4. Check CORS configuration in `backend/config/cors.php`

### Issue: Backend can't connect to database

**Symptoms:** 500 errors, database connection errors

**Solution:**
1. Verify database service is running
2. Check database environment variables are set correctly
3. Ensure migrations ran successfully (check backend logs)
4. Database credentials are auto-populated from `render.yaml`

### Issue: Migrations failed

**Symptoms:** Tables missing, errors about missing columns

**Solution:**
1. Check backend logs for migration errors
2. Manually run migrations:
   - Go to backend service → Shell
   - Run: `php artisan migrate --force`
3. If needed, run seeders: `php artisan db:seed --force`

### Issue: Build failed

**Backend Build Failed:**
- Check PHP version (should be 8.2+)
- Verify `composer.json` is valid
- Check for missing dependencies

**Frontend Build Failed:**
- Check Node version (should be 20.19.0+)
- Verify `package.json` is valid
- Check for build errors in logs

### Issue: Environment variables not working

**Solution:**
1. After updating environment variables, restart the service
2. For frontend: Rebuild is required (environment variables are baked into build)
3. Clear Laravel cache: `php artisan config:clear`

## Production Optimizations

### Backend

1. **Enable Caching:**
   ```bash
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```

2. **Optimize Autoloader:**
   ```bash
   composer install --optimize-autoloader --no-dev
   ```

3. **Set APP_DEBUG=false** (already in render.yaml)

### Frontend

1. **Build is optimized** by default with Vite
2. **Environment variables** are replaced at build time
3. **Static assets** are served efficiently

## Custom Domains

To use custom domains:

1. **Backend:**
   - Go to backend service → Settings → Custom Domains
   - Add your domain (e.g., `api.yourdomain.com`)
   - Update DNS records as instructed

2. **Frontend:**
   - Go to frontend service → Settings → Custom Domains
   - Add your domain (e.g., `yourdomain.com` or `www.yourdomain.com`)
   - Update DNS records as instructed

3. **Update Environment Variables:**
   - Update `FRONTEND_URL` in backend
   - Update `SANCTUM_STATEFUL_DOMAINS` in backend
   - Update `VITE_API_URL` in frontend (rebuild required)
   - Update Google OAuth redirect URI

## Database Persistence & Backups

**Important:** Your database data is automatically persisted and backed up on Render!

- ✅ **Data Persistence**: All data is stored on durable disk volumes
- ✅ **Automatic Backups**: Daily backups are created automatically
- ✅ **7-Day Retention**: Backups are kept for 7 days (Starter Plan)
- ✅ **Easy Restore**: Restore from any backup via Render dashboard
- ✅ **No Manual Work**: Everything happens automatically

**Even if PostgreSQL stops or restarts, your data remains safe and accessible!**

For detailed information, see: `DATABASE_PERSISTENCE_GUIDE.md`
